# Adyapan Onboarding Portal security audit

Reviewed repository commit `86287b3`, the local running portal, both npm dependency sets and the existing end-to-end suite. Severity reflects the sensitivity of the uploaded identity documents, the access a person would need, and the number of records affected. This review found risks in the application design. It did not establish that anyone accessed records improperly.

| Priority | Finding and impact | Remediation and acceptance check |
| --- | --- | --- |
| High | **Invitation access outlives onboarding.** The QR or invitation token plus its matching email address can create a fresh session for any application past the queued stage, including an issued application. The separate 48-hour email link has expiry and single-use protection, but these checks do not govern the QR path. Someone who obtains both values can reopen the intern’s identity documents. [Invitation verification](../backend/services/access-mail.ts) | Give invitations a server-enforced expiry and an HR revocation action that also invalidates active sessions. For an intern returning after submission, use a passkey or the existing fresh email link. Verify that a retired QR cannot open a session and that legitimate returning interns can still download their letter. |
| High | **One password authorizes bulk HR export and countersigning.** The application recognizes one configured HR identity. Its session grants access to every received record, identity document export and offer issuance. Issuance records the configured email, so it cannot distinguish staff if credentials are shared. [HR login and export authorization](../backend/api/actions.ts) · [Issuance audit event](../backend/services/flow.ts) | Use named staff identities with passkeys or organization SSO. Grant bulk export and countersigning separately, and record the acting staff ID. Verify that a reviewer without those permissions can review a submission but cannot export the roster’s files or issue an offer. |
| Medium | **File acceptance precedes content screening.** PDF validation checks readability and page count. Image validation checks identifying bytes. Accepted originals become available for HR preview and download without an application-level malware scan. [Upload validation](../backend/services/private.ts) | Quarantine new files pending a scan, validate complete image structure and enforce PDF processing limits. Make preview, export and countersigning require a clean result. Verify that an unavailable scanner leaves a file pending. |
| Medium | **Repeated uploads accumulate private records.** Each replacement stores a new object. The application has a per-file limit, but no cumulative per-invitation limit. Storage is written before database metadata, so a failed transaction can also leave an unreferenced private object. [Storage and metadata writes](../backend/services/flow.ts) | Enforce per-invitation byte and version limits and reconcile unreferenced objects. Define retention separately for superseded drafts and files referenced by signed submissions. Verify that cleanup preserves every referenced signed record. |
| Medium | **Bulk document access lacks an application audit trail.** HR export includes historical uploads and declaration snapshots across all received records. The export and file-read handlers do not record who requested the export or which records it covered. [Export scope](../backend/services/received-export.ts) · [Download handlers](../backend/api/actions.ts) | Log the staff ID, timestamp, export scope, file count and outcome to a restricted audit log. Keep document contents, invitation tokens and identity numbers out of logs. Verify an export is attributable to one person. |

## Controls checked

- The file handler authenticates the requested role and restricts intern reads by invitation. Session tokens are randomly generated and stored as hashes. Cookies are HttpOnly, SameSite=Lax and Secure in production mode.
- State-changing requests check the request origin and enforce a streamed body-size limit. Offer issuance checks the reviewed file ID and submission revision. The roster importer limits workbook size, archive entries and row count.
- All four existing Playwright tests passed against isolated local fixtures. They cover expired email links, incorrect HR passwords, rejected cross-intern file access, submission and issuance, and matching copies of the issued PDF.
- npm reported zero known advisories for production dependencies and for the full dependency tree. A limited check of tracked files found no matches for common private-key, AWS access-key ID or GitHub token patterns. It did not cover Git history or provider-held secrets.
- The local HR page returned anti-framing, MIME-sniffing and referrer-policy headers. Its HTML response lacked a page-level Content Security Policy. Introduce a report-only policy first and check PDF previews, downloads and Next.js scripts before enforcing it.

## Production verification still open

The production endpoint and administrator-side settings were unavailable during this review. Verify HTTPS and response headers on the deployed domain, access restrictions on Vercel preview deployments, redaction of invitation URLs from logs, database TLS and backup access, and private-bucket public-access blocking, IAM permissions and retention. Inspect a sample export audit event after logging is enabled.

The CodeRabbit installer rejected the Windows Git Bash environment as unsupported. CodeRabbit contributed no scan results. The checks above used local source inspection, npm advisory checks and the project’s regression suite.

## Remediation verified in the local portal

The application now requires a named HR account, password and personal access key. Server-side permissions and assignments cover roster access, file reads, exports and offer issuance. An HR login expires after eight hours. Export, signing and access revocation require credential verification within ten minutes. Old shared sessions are rejected.

Initial QR access is limited to a single claim of a blank invitation within 48 hours. Returning users get a single-use mailbox link. HR can retire all invitation links and sessions for a record. New document uploads undergo malware screening, PDF or image validation and file limits. Previously stored files receive screening at first access. The local manager successfully retrieved an existing issued letter after migration. File access and exports are recorded against the staff identity.

Storage reconciliation defaults to a dry run. The local pilot reported zero orphan objects and zero eligible draft versions. Production deployment, scanner connectivity and infrastructure controls still require validation against the actual hosting account. See the project README for provisioning and migration.
